# Cherry-pick merges to staging/main

Cherry-pick one or more merge commits and create a PR to staging or main branch via `gh`.

## When to use

- User invokes `/cherry-pick-merges` or asks to cherry-pick merge commit(s) onto `main` or `staging`.

## Required Information

**IMPORTANT**: The following information is REQUIRED and must be provided:

1. **Merge commit SHA(s)** - One or more git merge commit SHAs (space/comma/newline separated)
2. **Target base branch** - Either `main` or `staging` (no default, must be specified)

## Usage

In Agent chat, invoke this skill from `/` and provide:

- **SHAs**: Merge commit SHA(s) (space/comma/newline separated) - **REQUIRED**
- **Base**: Target base branch (`main` or `staging`) - **REQUIRED**
- **Branch**: Optional custom branch name (auto-generated if not provided)

## Example

```
/cherry-pick-merges
SHAs: ecde5e00edb5abedd1e0ddcb45ac9cbe2f159fba 935749d695136486aaa8fb892db5688f2c04f72c
Base: staging
```

## Input Validation

If required information is missing or invalid, prompt:

1. **Missing SHAs**: "Please provide the merge commit SHA(s) to cherry-pick"
2. **Missing Base**: "Please specify the target base branch (main or staging)"
3. **Invalid Base**: "Base branch must be either 'main' or 'staging'"
4. **Invalid SHAs**: "One or more provided SHAs are invalid or not merge commits"
5. **Missing gh**: "GitHub CLI (gh) is required for this command. Please install and authenticate with 'gh auth login'"

## Process

1. **Fetch all refs and prune deleted branches**
   - `git fetch --all --prune`

2. **Checkout target base branch and pull latest**
   - `git checkout <Base>` (either `main` or `staging`)
   - `git pull origin <Base>`

3. **Create new branch**
   - If no custom name is provided, auto-generate:
     - `chore/{base}-cherrypick-{short-shas}`
     - e.g., `chore/staging-cherrypick-ecde5e0-935749d`
   - Run:
     - `git checkout -b <cherrypick-branch>`

4. **Cherry-pick each merge commit with `-m 1` (mainline parent)**
   - For each SHA provided:
     - `git cherry-pick -m 1 <SHA>`
   - **Handle failures**:
     - If cherry-pick returns a non-zero exit code and there are conflicts:
       - Stop and inform the user:
         - "Cherry-pick resulted in conflicts. Please resolve manually on the cherry-pick branch."

5. **Push the cherry-pick branch**
   - `git push -u origin <cherrypick-branch>`

6. **Create the PR using GitHub CLI**
   - Detect repo from `git remote get-url origin`
   - Auto-generate PR title:
     - `chore: cherry-pick <short-shas> to <Base> (YYYY-MM-DD)`
     - Where `YYYY-MM-DD` is the current date in ISO format (e.g., `2026-04-15`)
   - Run:
     - `gh pr create --base <Base> --head <cherrypick-branch> --title "<auto-generated-title>" --body "Cherry-picked merge commit(s): <SHAs>"`

7. **Output / Share the PR link**
   - Capture the URL from `gh pr create` output
   - Display the PR link as a **clickable link** in the chat response (not plain text)
   - Print a clear summary, for example:
     - `Created PR to cherry-pick merge commit(s) to <Base>: <PR-URL>` (where `<PR-URL>` is displayed as a clickable link)

## Notes

- Uses `-m 1` to cherry-pick merge commits correctly (selects the mainline parent)
- Auto-generates branch names from first 7 chars of each SHA
- Detects GitHub repo from git remote URL
- Handles both git@ and https remote formats
- **Prereqs**: Requires `git` and `gh` to be installed and authenticated
